## Présentation publique de réservation
- `washers.booking_page_mode` : `default` pour le parcours compact, `custom` pour la présentation classique personnalisable. Colonne en base depuis le 2026-10-03 (migration appliquée directement via l'API Management Supabase, pas de fichier dans `supabase/migrations/` — convention du projet : SQL donné en direct, jamais commité).
- **Politique de bascule (Alexandre, 2026-10-04)** : les laveurs déjà inscrits gardent leur page personnalisée par défaut (`custom`) — ils l'activent eux-mêmes via la case « Page par défaut » de leurs réglages s'ils le veulent. Les nouvelles inscriptions démarrent directement sur la nouvelle page (`default`, écrit explicitement dans `api/auth/signup/route.ts`) et peuvent revenir à la personnalisation en désactivant la même case. Aucune liste d'exception dans le code : la colonne, correcte par construction à l'inscription, décide seule — `bookingPageMode(value)` la lit directement, sans détour. (Historique : du 2026-10-03 au 2026-10-04, `COMPTES_TEST_NOUVELLE_PAGE_RESERVATION` limitait la nouvelle page à deux comptes de test le temps de vérifier qu'elle ne faisait perdre la personnalisation de personne ; retirée une fois les 24 comptes existants ramenés à `custom` en base.)
- Un interrupteur (pas une case à cocher) « Page par défaut », toujours visible désormais : actif = default, inactif = custom avec les réglages visibles. Commun à `IdentiteForm` (web) et `ApparenceV2` (PWA), via `BookingPageModePicker` et PATCH /api/washer. Changer le mode ne supprime jamais les réglages d'apparence. Logo et Couleur restent modifiables quel que soit le mode (depuis le 2026-10-04) ; Fond et Message d'accueil restent réservés au mode custom, la nouvelle page ne s'en sert pas encore.
- La route `/book/[slug]` charge et contrôle les données une seule fois, puis rend `BookingForm` ou `LegacyBookingPage`. Garder les listes explicites des champs envoyés aux composants clients.
- `e2e/booking-refonte.spec.ts` (Playwright, config `playwright.refonte.config.ts`) : seul test de bout en bout sur ce parcours, sur données fictives (`/dev/booking-preview`). À rejouer après toute modification de `BookingPageModePicker`, `IdentiteForm` ou `ApparenceV2` : deux régressions silencieuses (rôle ARIA du contrôle, slug hors d'une liste depuis retirée) y sont passées inaperçues jusqu'au 2026-10-04, faute d'avoir été rejoué.
